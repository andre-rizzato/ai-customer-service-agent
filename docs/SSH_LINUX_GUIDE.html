1. Conectando via SSH

SSH (Secure Shell) é como você abre um terminal dentro da VM, de dentro do seu próprio terminal. O comando usado neste projeto:

ssh -i ~/.ssh/id_rsa azureuser@20.127.12.103
ParteO que é
-i ~/.ssh/id_rsaCaminho da sua chave privada — a "senha" criptográfica que autentica você na VM, sem precisar digitar senha nenhuma
azureuserUsuário do sistema operacional dentro da VM
20.127.12.103IP público da VM (vm-agente)
Primeira conexão Na primeira vez, o terminal pergunta se confia no "host" (a VM) — responda yes. Isso fica salvo em ~/.ssh/known_hosts e não pergunta de novo.
A chave privada nunca sai da sua máquina ~/.ssh/id_rsa é o que garante que só você entra na VM. Não copie, não cole em chat nenhum, não mande por email.

Pra sair da VM e voltar pro seu terminal normal: exit ou Ctrl+D.

2. Navegação e arquivos

ComandoO que faz
pwdMostra em qual pasta você está agora
ls / ls -laLista arquivos da pasta atual (-la: inclui ocultos, com detalhes — dono, tamanho, data)
cd nome-da-pastaEntra numa pasta. cd .. sobe um nível, cd ~ vai pra sua pasta pessoal (/home/azureuser)
mkdir nomeCria uma pasta nova
cp origem destinoCopia um arquivo. cp -r copia pasta inteira
mv origem destinoMove ou renomeia (não existe comando "renomear" separado — mv faz os dois)
rm arquivoApaga um arquivo. rm -r pasta apaga pasta inteira — sem lixeira, é definitivo
find . -name "*.log"Procura arquivos por nome, a partir da pasta atual
Cuidado com rm -rf Apaga sem pedir confirmação e sem lixeira. Antes de rodar, confirme com pwd e ls que está na pasta certa.

As duas pastas que importam neste projeto:

~/agente-atendimento/   # o agente Node (RAG + LLM + canais)
~/agent-service/        # o AgentService Python (DistributedOrderSystem)

3. Ver e editar conteúdo

ComandoO que faz
cat arquivoMostra o conteúdo inteiro de uma vez — bom pra arquivos curtos (.env, agent.config.json)
less arquivoMostra um arquivo grande por partes, navegável (setas, q pra sair)
tail -n 20 arquivoMostra só as últimas 20 linhas
tail -f arquivoMostra as últimas linhas e continua mostrando em tempo real — ótimo pra acompanhar log ao vivo
nano arquivoAbre um editor de texto simples direto no terminal — Ctrl+O salva, Ctrl+X sai
grep "termo" arquivoProcura um texto dentro de um arquivo. grep -r "termo" pasta/ procura em todos os arquivos de uma pasta
Editar .env ou agent.config.json nano ~/agente-atendimento/.env → edita → Ctrl+O, Enter, Ctrl+X. Depois de editar, sempre reinicie o processo (Seção 4) pra aplicar.

4. Processos com PM2

PM2 é quem mantém o agente Node e o AgentService rodando continuamente, reinicia sozinho se travar, e sobrevive a reboot da VM.

ComandoO que faz
pm2 listMostra todos os processos — status (online/stopped), uso de CPU/memória, quantas vezes reiniciou
pm2 logs nomeMostra os logs ao vivo de um processo (Ctrl+C pra sair)
pm2 logs nome --lines 50 --nostreamMostra as últimas 50 linhas e volta pro terminal (não fica "preso" acompanhando)
pm2 restart nomeReinicia um processo — necessário depois de editar .env ou agent.config.json
pm2 restart nome --update-envIgual acima, mas também recarrega variáveis de ambiente novas (ex.: depois de adicionar um secret no Key Vault)
pm2 stop nome / pm2 start nomePara e liga um processo, sem removê-lo da lista
pm2 saveImportante depois de qualquer mudança — grava o estado atual pra sobreviver a um reboot da VM

Os dois processos deste projeto: agente-atendimento e agent-service.

6. Sistema — memória, disco, serviços

ComandoO que faz
free -hMemória RAM usada/livre (-h: formato legível, MB/GB). A VM é pequena (892MB) — confira antes de instalar algo pesado
df -hEspaço em disco usado/livre
uptimeHá quanto tempo a VM está ligada, e carga média de CPU
topLista processos ao vivo por uso de CPU/memória (q pra sair)
systemctl status nomeStatus de um serviço do sistema (ex.: nginx, pm2-azureuser)
sudo systemctl restart nomeReinicia um serviço do sistema
VM pequena — cuidado com instalação/build Já tivemos um incidente de memória esgotada rodando npm ci com os processos ativos ao mesmo tempo. Antes de instalar algo pesado, considere pm2 stop nos dois processos, e confira free -h antes e depois.

7. Rede e testes

ComandoO que faz
curl -s URLFaz uma requisição HTTP e mostra a resposta — útil pra testar se o servidor está respondendo
curl -s -o /dev/null -w "%{http_code}\n" URLMostra só o código de status HTTP (200, 404, 500...), sem o corpo da resposta
curl -I URLMostra só os headers da resposta
ss -tlnpLista quais portas estão escutando na VM (equivalente moderno do antigo netstat)
ping -c 4 hostTesta se um host responde na rede (4 tentativas)

Pra conferir se o agente está de pé, de dentro da própria VM:

curl -s http://localhost:3000/health
curl -s http://localhost:8100/health

8. Nginx e certificado TLS

ComandoO que faz
sudo nginx -tTesta se a configuração do Nginx está válida, antes de recarregar — evita derrubar o site com um erro de sintaxe
sudo systemctl reload nginxAplica mudanças de configuração sem derrubar conexões ativas
sudo certbot certificatesLista os certificados TLS instalados e quando expiram
sudo certbot renew --dry-runTesta a renovação automática sem renovar de verdade (a renovação real já roda sozinha agendada)

9. Git

ComandoO que faz
git statusMostra o que mudou localmente, comparado ao último commit
git pullBaixa e aplica os commits mais recentes do GitHub
git log --oneline -10Mostra os últimos 10 commits, resumidos
Normalmente você não precisa disso na VM O deploy é automático via GitHub Actions a cada push — a VM se atualiza sozinha. git pull manual só é necessário se estiver investigando algo ou testando antes do CI rodar.

10. Receitas prontas — rotina real do projeto

Editei o .env ou agent.config.json, como aplico?

pm2 restart agente-atendimento --update-env
pm2 save

Adicionei um secret novo no Key Vault, como o processo pega ele?

pm2 restart agente-atendimento --update-env
# (o processo busca os secrets do Key Vault de novo, no startup)

O site/bot parece fora do ar — o que eu confiro, em ordem?

1
pm2 list — os dois processos estão online?
2
curl -s http://localhost:3000/health — responde {"ok":true}?
3
pm2 logs agente-atendimento --lines 30 --nostream --err — tem erro recente?
4
free -h — a VM não está sem memória?

A VM ficou lenta ou travou depois de instalar algo

free -h                                  # confirma se é falta de memória
pm2 stop agente-atendimento agent-service  # libera memória
# ... termina a instalação/build ...
pm2 restart agente-atendimento agent-service --update-env
pm2 save

Atualizar o código manualmente (fora do CI/CD automático)

cd ~/agente-atendimento
git pull
npm ci
npm run build
pm2 restart agente-atendimento --update-env
pm2 save

Conferir se o certificado HTTPS está válido

sudo certbot certificates
curl -sI https://rizzato-tech.rizzatotech.com | head -1

11. Segurança e boas práticas

  • Nunca cole senha, token ou chave de API direto no terminal de um jeito que fique salvo no histórico sem necessidade — prefira variável de ambiente ou o Key Vault
  • sudo só quando o comando realmente precisar — não vire hábito de colocar na frente de tudo
  • Antes de qualquer rm -r, confirme com pwd e ls que está na pasta certa
  • A chave privada (~/.ssh/id_rsa) é pessoal — nunca envie por chat, email ou deixe em repositório
  • Depois de qualquer mudança que deva sobreviver a um reboot da VM, rode pm2 save
